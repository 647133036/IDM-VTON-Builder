# Requirements Document

## Introduction

This feature is a web-based virtual try-on dashboard embedded inside an existing e-commerce clothing store admin. The system SHALL accept bulk flat-lays or ghost-mannequin shots and generate one clean, front-facing photo of a realistic model wearing each garment. The tool SHALL support women's, men's and children's lines (baby & toddler, boys, girls), process bulk uploads with a visible queue, and let staff download or push finished PNG/JPEG outputs directly into product pages. All image generation SHALL run server-side on the merchant's own cloud account.

## Glossary

- **System**: The Atelier virtual try-on dashboard, composed of a browser-based admin UI and a server-side generation engine.
- **Admin staff**: Store employees granted access through the secure login inside the existing store admin.
- **Garment photo**: A flat-lay or ghost-mannequin shot uploaded by admin staff.
- **Output image**: A single front-facing photo of a realistic model wearing a given garment, generated by the System.
- **Base / model base**: A stored model portrait template used as the body onto which the garment is rendered.
- **Queue**: The ordered list of submitted generation tasks visible in the dashboard.
- **Byte-level background**: The output background, either transparent (alpha channel) or solid white.

## Requirements

### Requirement 1: Secure login

**User Story:** AS admin staff, I want a secure login embedded in the store admin, SO THAT only authorized staff can access the tool.

#### Acceptance Criteria

1. WHEN staff open the dashboard, the System SHALL require a valid username and password before showing any project data.
2. WHEN staff submit incorrect credentials, the System SHALL reject the login and SHALL NOT reveal which field was wrong.
3. WHEN staff hold a valid session token, the System SHALL allow access to all admin routes.
4. WHEN the session token is missing, expired or invalid, the System SHALL return an unauthorized response for protected routes.

### Requirement 2: Bulk drag-and-drop upload

**User Story:** AS admin staff, I want to upload dozens or hundreds of garment photos in one drag-and-drop action, SO THAT I can process a large batch without repeated interactions.

#### Acceptance Criteria

1. WHEN staff drag and drop garment photos onto the upload area, the System SHALL accept multiple image files in one action.
2. WHEN staff drop files with unsupported formats, the System SHALL reject each unsupported file and report the rejected file names.
3. WHEN staff drop a batch containing valid images, the System SHALL create one generation job per garment photo.
4. WHEN the batch contains more than one garment photo, the System SHALL mark all jobs as queued and process them in order.

### Requirement 3: Audience recognition

**User Story:** AS admin staff, I want the tool to recognise women's, men's and children's garments automatically, SO THAT kids' lines are handled correctly without manual labelling.

#### Acceptance Criteria

1. WHEN staff submit any garment photo, the System SHALL classify it under a best-guess audience of women, men, girls, boys or baby/toddler.
2. WHEN staff submit a children's garment, the System SHALL assign the child-applicable audience automatically without manual override.
3. WHEN the base or source suggests a different audience than the default, the System SHALL resolve the audience from the base before generation.
4. WHEN staff explicitly select an audience, the System SHALL use the explicit selection and override automatic classification.

### Requirement 4: Single front-facing output

**User Story:** AS admin staff, I want exactly one clean front-on model shot per garment, SO THAT I can publish a consistent product image.

#### Acceptance Criteria

1. WHEN a generation job completes, the System SHALL return exactly one front-facing model image per input garment.
2. WHEN a generation job completes, the System SHALL NOT produce side or back angle images.
3. WHEN generating an output, the System SHALL preserve natural body proportions relative to the selected base.
4. WHEN generating an output, the System SHALL render a realistic fabric drape that follows the garment silhouette.
5. WHEN generating an output, the System SHALL keep colour fidelity close to the original garment photo.

### Requirement 5: Bulk processing and queue progress

**User Story:** AS admin staff, I want to watch batch progress in a queue, SO THAT I know when each garment is ready.

#### Acceptance Criteria

1. WHEN staff submit a batch, the System SHALL display the ordered queue with one entry per garment.
2. WHILE a job is being processed, the System SHALL update its status and progress in the queue.
3. WHEN a job finishes, the System SHALL mark it done and expose its output for download.
4. WHEN a job fails, the System SHALL mark it failed with a message describing the failure.
5. WHEN staff load the dashboard, the System SHALL reflect current queue state including queued, running, done and failed jobs.

### Requirement 6: Parallel server-side generation

**User Story:** AS a store operator, I want the generation engine to process jobs in parallel, SO THAT batch throughput scales with available compute.

#### Acceptance Criteria

1. WHEN multiple jobs are queued, the System SHALL process independent jobs concurrently across available worker slots.
2. WHEN the number of queued jobs exceeds worker capacity, the System SHALL hold the remainder in queue order.
3. WHEN a generation job is processing, the System SHALL run it on the server, not in the browser.
4. WHEN the engine backend starts with one command, the System SHALL start the API, the worker pool and all storage initialisation in a single launch step.

### Requirement 7: Output specifications

**User Story:** AS admin staff, I want outputs that meet store publishing requirements, SO THAT I can upload them directly to product pages.

#### Acceptance Criteria

1. WHEN a job completes, the System SHALL emit an image with a longest side of at least 2048 pixels.
2. WHEN staff or settings request transparent background, the System SHALL emit PNG output with an alpha channel.
3. WHEN staff or settings request a solid background, the System SHALL emit white-background output.
4. WHEN staff request JPEG output, the System SHALL emit a JPEG image.

### Requirement 8: Download and push to product pages

**User Story:** AS admin staff, I want to download outputs or push them straight into product pages, SO THAT I can publish finished images efficiently.

#### Acceptance Criteria

1. WHEN a job is done, the System SHALL provide a direct download link for its output image.
2. WHEN a job is done, the System SHALL allow staff to attach a SKU and product URL and push metadata to the product page.
3. WHEN staff push a job that is not finished, the System SHALL reject the push with a message that only completed outputs can be pushed.
4. WHEN staff push a finished job, the System SHALL record the SKU and mark the job as pushed.

### Requirement 9: Secure deployment and data control

**User Story:** AS a store operator, I want all processing on my cloud account with secure access, SO THAT I keep control of data and compute costs.

#### Acceptance Criteria

1. WHEN the System is deployed, it SHALL run in the merchant's cloud account (AWS, GCP or Azure).
2. WHEN processing an image, the System SHALL keep the source and output inside the merchant-owned storage.
3. WHEN the System stores credentials, the System SHALL keep secrets out of version control and source code.
4. WHEN staff access the tool, the System SHALL authenticate through the embedded secure login.

### Requirement 10: Throughput acceptance

**User Story:** AS a store operator, I want reliable batch throughput, SO THAT the tool is production-ready.

#### Acceptance Criteria

1. WHEN a 100-item test batch is submitted, the System SHALL convert at least 95 items into high-quality, front-facing model images ready to publish.
2. WHEN a job completes, the System SHALL expose the output through a stable URL that survives staff re-login.

### Requirement 11: Kids proportions and background synthesis

**User Story:** AS admin staff, I want correct child body proportions and clean backgrounds, SO THAT kids' pieces and studio shots look realistic.

#### Acceptance Criteria

1. WHEN the audience is baby/toddler, boys or girls, the System SHALL use child-appropriate proportions for the output body.
2. WHEN the source garment photo has no clean background, the System SHALL remove the background and synthesize either a white background or a transparent channel.
3. WHEN the source garment photo needs segmentation, the System SHALL use the backend image processing pipeline to isolate the garment.

### Requirement 12: Audience-specific garment fit quality

**User Story:** AS admin staff, I want output images where the garment fits the model realistically for its target audience, SO THAT the photos look like real product shots instead of a distorted or "scaled-down adult" rendition.

#### Acceptance Criteria

1. WHEN the audience is adult women and the garment is a dress or one-piece, the System SHALL preserve the waistline, skirt hem drape and collar or strap fit of the garment.
2. WHEN the audience is adult women and the garment has a fitted bodice, the System SHALL keep the waist and chest seams aligned with the body silhouette.
3. WHEN the audience is adult men and the garment is a shirt, jacket or coat, the System SHALL render crisp shoulder lines, correct shoulder-width proportion and a structured silhouette rather than a soft or slouchy fit.
4. WHEN the audience is men and the garment has sleeves, the System SHALL keep sleeve length proportional to the model base.
5. WHEN the audience is children (baby/toddler, boys, girls), the System SHALL render the garment with child-appropriate head-to-body ratio, limb length and fullness, so that the outfit reads as a garment cut for a child rather than a scaled-down adult garment.
6. WHEN the audience is young men and the garment is an oversized fit such as hoodies or loose outerwear, the System SHALL render the dropped-shoulder effect and relaxed drape naturally.
7. WHEN the audience is young adults and the pose is dynamic, the System SHALL keep garment geometry stable and natural in motion rather than distorted.
8. WHEN the audience is young women, the System SHALL handle both fitted and oversized silhouettes, keeping the fit natural under casual poses.
9. WHEN the audience is not explicitly specified, the System SHALL derive the fit quality rules from the selected base audience label.
